# Skill authoring standard

Every new skill must stay within AI-slop recognition, diagnosis, or remediation.

1. Give it a distinct problem boundary; do not add generic PM, backend, or unrelated coding skills.
2. Use valid frontmatter (`name`, `description`, and applicable `license`).
3. Explain when to use it and its scope.
4. Provide a concrete ordered workflow with observable checks.
5. Treat AI-origin claims cautiously; never infer authorship from styling tropes.
6. State what must be preserved and what must not be fabricated.
7. Define output expectations and a completion bar.
8. Mention tool-dependent fallbacks without assuming browser or image access.
9. Add a realistic prompt to `examples/prompts.md` when it introduces a new workflow family.
10. Run both repository validation and security scans before submitting.
